# Contributing to Scantrix

Thank you for your interest in contributing to Scantrix.

Scantrix is an actively maintained project with a defined product direction. Contributions are welcome, but should align with the goals of improving automation quality, reliability, and maintainability.

---

## Before You Start

Please open an issue before working on:

- New features
- Significant refactors
- Changes to core behavior

This ensures alignment and avoids duplicate or conflicting work.

---

## Types of Contributions

We welcome:

- Bug fixes
- Improvements to existing rules or detection logic
- Performance improvements
- Documentation improvements
- Test coverage enhancements

We are selective with:

- New rules (must be high-signal and broadly applicable)
- Architectural changes
- Opinionated or niche patterns

---

## Development Guidelines

- Use clear, readable TypeScript
- Avoid unnecessary abstraction
- Prefer explicit logic over cleverness
- Follow existing project patterns and structure

---

## Testing

All changes should include appropriate validation:

- Unit or integration tests where applicable
- No breaking changes to existing behavior unless discussed

---

## Pull Requests

When submitting a PR:

- Link the related issue
- Clearly describe what was changed and why
- Keep changes focused and minimal
- Ensure all checks pass

PRs that do not follow these guidelines may be declined.

---

## Maintainer Review

Maintainers reserve the right to:

- Request changes
- Decline contributions that do not align with the project direction
- Prioritize consistency and long-term maintainability over feature expansion

---

## Questions

If you're unsure about an idea, open an issue first to discuss it.
